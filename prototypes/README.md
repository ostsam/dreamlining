# Dreamlining prototype takes

These are draft, non-binding HTML prototypes for the agreed product behavior. Each has a persistent `PROTOTYPE` badge and uses realistic mock data; nothing is connected to Neon or real sessions.

- `01-roomboard.html` — room-first: participants see the event rhythm and a balanced “next contribution” prompt.
- `02-dream-gallery.html` — gallery-first: the room is a browsable collection with adaptive ordering and an explicit seen-without-comment shelf.
- `03-guided-inbox.html` — focus-first: one dreamline at a time with a personal queue, while browse-all remains one tap away.
- `04-admin-control-room.html` — shared admin boundary: password gate, session creation, QR, live coverage, phase controls, and report moderation.
- `05-admin-login.html` — the `/admin` arrival state: a small trusted-host password gate with clear recovery copy.

Open each file in a browser. The primary interactions are wired as small local state changes: phase tabs, public/private comment toggles, contact-request approval, and commitment selection.
